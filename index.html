Permissionless ledgers for people and AI agents

Ship the app.
Skip the backend.

Every app drags a backend behind it: servers to defend, a database to run, a payment processor to integrate, and passwords to protect. The bill grows with every user, and every bot.

Lattice is that backend as an open network: anyone can run a node, and no one has to ask. You ship the page; people and AI agents bring their own keys and pay as they go.

The problem

Most of a backend is overhead.

Little of a typical backend is your product. The rest keeps attackers out, keeps data alive, moves money, and guards logins. You pay for it whether your app takes off or not, and you answer for it when it breaks.

What you still write

Only the part that is your product.

  • Your rulesWhat counts as a valid action in your app: who may edit what, what a ticket costs, who can resell it. Every node enforces them, so no one, including you, can quietly break them.
  • Your pageStatic files, hosted anywhere. It reads data it can verify and asks the user’s wallet to sign and pay.

Your rules get a ledger of their own: a public record of keys and values that every node checks against those rules. Lattice calls it a chain. Another app’s rush never competes with yours for space.

Miners can secure it alongside Nexus, the root ledger, from its first block, with no validators to recruit. Its security is the hashpower that chooses to mine it.

Don’t need custom rules? Write to a ledger that already has the right ones. The apps here share Moniker’s for profiles.

Built for agents

An agent is just another key.

Today an agent stalls at every signup form, API key, and card field, because each one was built to make sure a human is there. Lattice asks for none of them.

Nothing to sign up for

An agent makes its own key and starts working. Where nodes accept zero-fee writes, it needs no money to begin.

Pays as it goes

Any action can carry a payment: buy a ticket, tip a post, rent a spot. No invoices, no account to top up.

Doesn’t have to trust you

Every value it reads is checked against its hash, so a stranger’s node can’t forge data. At worst it serves an old tip, which asking a second node catches.

Command-line setup

From nothing to a live app.

The command-line tools build from source with Swift 6.1 or newer, on macOS 15+ or Linux. (Just want a node and a wallet? Lattice Desktop runs both with no setup.) Develop under Nexus/testnet: once a chain launches, its rules can never change.

  1. Build and start a node

    With no peers set, the node joins the public Nexus network. A node hosts a chain only under a parent it hosts, so add the public testnet before you start it.

  2. Write your rules

    A chain is a JSON spec: block time, rewards, size limits, and the CIDs of its policy modules. Policies are WASM modules; the examples are written in Rust. Start from Moniker’s policy/ crate, or let the lattice-app-builder skill write one with you.

  3. Launch the chain

    The node starts hosting it immediately. To fund an account in genesis, set premine in the spec and name the account with --premine-to <address>.

  4. Mine it, or let others

    A chain advances when someone mines it. Make a key, pay the chain’s rewards to it, and start the bundled CPU miner; GPU miners can merge-mine it alongside Nexus. A chain with no recipient burns its rewards.

  5. Ship a page

    Read with the TypeScript SDK, which checks every value against the chain tip. Write with window.lattice from the user’s wallet. Host the page anywhere static files go.

Before you build

When Lattice is the wrong choice.

  • You need instant confirmation. A write takes effect in the next block: about a minute on the testnet app ledgers today, and an hour on average on Nexus.
  • You need a write to be final. Lattice follows the chain with the most proof of work, and a heavier competing history can replace recent writes. Confirm important ones by reading them back.
  • You need to charge in dollars. Payments are in the coin of the ledger they happen on. Users get it by mining, from another user, or by trading for it; there is no card on-ramp.
  • You need to change your rules later. A launched ledger’s rules are fixed. To change them, launch a new ledger and have your page read both.
  • You need private data. Everything on a chain is public. Encrypt it yourself before you write it.
  • You need code that runs on its own. Your rules can only accept or reject an action. Feeds, ranking, matching, and anything scheduled run in your page or your own service.
  • You need someone else to keep it running. A chain lives while people mine and host it. A small chain is only as secure as the hashpower that chooses to mine it.
  • You need stability today. Lattice is pre-1.0. Networks have been reset at protocol upgrades, the SDK is not yet on npm, and the command-line tools build from source.
